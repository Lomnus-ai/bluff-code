# bluff-code — Design Document

> 中文版本：[DESIGN.zh.md](./DESIGN.zh.md)（英文为权威版本）

> **Status:** Draft v0.1 · 2026-05-03
> **Owner:** Lomnus AI
> **Stack:** Bun + TypeScript + React + Ink (mirrors Claude Code)

---

## 1. Overview

`bluff-code` is a terminal CLI that mimics the visual experience of an AI coding
assistant — streaming tokens, scripted tool calls, spinners, boxed input, the
works — without any model behind it. All output is generated by a deterministic
rule engine over a library of templates and scripted scenarios.

The whole product is a sustained joke that has to land at a glance and survive
a moderately attentive second look.

---

## 2. Goals & Non-Goals

### Goals

- **Visual fidelity.** Indistinguishable from real Claude Code at a glance.
- **Zero subscription.** No API keys, no network calls, runs offline.
- **Plausible motion.** Streaming, jitter, spinners, tool-call sequences that
  feel like real model output, not a teleprompter.
- **Repo awareness.** Output references real files in the user's working
  directory so the bluff survives an over-the-shoulder check.
- **Comedic range.** Multiple voices ("vibes") shippable from day one.

### Non-Goals

- Not an LLM proxy. We never call a model.
- Not a code-modifying tool. We never write to user files. (We *read* them — see §10.)
- Not a network tool. No telemetry, no fetches, no auth.


---

## 3. Primary Use Cases

We optimize for **(a)** and **(d)** from the use-case slate. Everything else is
served opportunistically.

### (a) Cafe-bluffer / look-busy

The user wants their terminal to *look* like a serious coding session while
they are away from the keyboard, distracted, or being observed. Implications:

- Must run **without input** for long stretches → ambient loop mode (§6.3).
- Must reference **real local files** to pass over-the-shoulder inspection (§10).
- Must **never block** waiting for input.
- Recovery from `Ctrl+C` should look graceful, not crash-y.

### (d) Comedy / satire

The user wants to record clips, screenshot transcripts, or live-stream
content where the joke is "look, I made a fake AI." Implications:

- **Vibes** are first-class — the joke gets sharper with `--vibe doomer` etc.
- Determinism via seed is needed for reproducible takes.
- Tool-call mimicry must be high-fidelity; subtle-wrong details ("Reading…
  banana.ts") sell the satire.

### What this excludes

- We're not building for the unscripted "explain my actual code" case. That
  needs an LLM. If a user wants real responses, they should use real Claude.

## 4. Design Decisions (locked answers)

| # | Decision | Choice |
|---|---|---|
| 1 | Primary use cases | (a) cafe-bluffer + (d) comedy/satire |
| 2 | Modes | Both REPL and one-shot, switchable via CLI flag; default one-shot. (Plus ambient — see §6.3.) |
| 3 | Real-world context | **Heavy** (read file contents) with strict guardrails (§10) |
| 4 | Session state | **Stateful** within a single REPL session |
| 5 | Determinism | **Randomized** by default; seedable via `--seed N` |
| 6 | Tool-call fidelity | **Full mimicry** — Read / Grep / Edit / Bash blocks with spinners and ✓ marks |
| 7 | Vibes | Day-one set of vibe packs (§9) |

## 6. Modes

### 6.1 One-shot (default)

```bash
bluff "fix the auth bug in login flow"
```

- Runs one scenario end-to-end, then exits.
- Best for: scripts, screenshots, recordings, README demos.
- No persistent state across invocations.
- Streams to stdout; can pipe (`bluff "..." | tee transcript.txt`).

### 6.2 REPL

```bash
bluff --repl
```

- Boxed input area at bottom (Ink), scrollback above.
- Slash commands: `/clear`, `/vibe <name>`, `/seed <n>`, `/exit`, `/init`,
  `/plan` (cosmetic only — see §13).
- Multi-turn, **stateful** (§11).
- Best for: live cosplay, comedy streams, demos that need user-driven beats.

### 6.3 Ambient (no args)

```bash
bluff
```

- No input expected. Loops scripted scenarios indefinitely with realistic
  inter-arc pauses.
- Pulls real file paths from cwd to make each arc look like fresh work.
- Designed for **leave-laptop-open at the cafe**.
- `Ctrl+C` exits cleanly with a fake "Session ended" message.
- Open question (§14): is this its own mode or `bluff --ambient` that defaults
  on with no prompt? Going with **no-args = ambient** for now.

### 6.4 Mode flags

| Flag | Behavior |
|---|---|
| (no args) | Ambient loop |
| `<prompt>` | One-shot |
| `--repl`, `-i` | REPL |
| `--once <prompt>` | Explicit one-shot (same as bare prompt) |
| `--ambient` | Explicit ambient |
| `-C <path>`, `--cwd <path>` | Use `<path>` as the codebase root (default: `process.cwd()`) |
| `--vibe <name>` | Pick vibe pack (default: `default`) |
| `--seed <n>` | Pin RNG for reproducible output |
| `--sandboxed` | Disable filesystem reads (heavy → none) |
| `--no-color` | Plain output |
| `--version`, `-v` | Print version |
| `--help`, `-h` | Help |

## 7. Data Model (high-level)

These are shapes, not implementations. Real types ship in code.

```ts
// A unit of scripted output.
type Beat =
  | { kind: 'chat',         text: string,   markdown?: boolean }
  | { kind: 'tool',         tool: ToolCall, render: ToolRender }
  | { kind: 'pause',        ms: number }
  | { kind: 'thinking',     label?: string,  ms: number }
  | { kind: 'ask',          question: string, fakeAnswer: string }
  | { kind: 'permission',   summary: string,  outcome: 'allow' | 'deny' }

type ToolCall =
  | { name: 'Read',   path: string }
  | { name: 'Grep',   pattern: string, glob?: string }
  | { name: 'Edit',   path: string, additions: number, removals: number }
  | { name: 'Bash',   cmd: string,  fakeOutput: string[] }
  | { name: 'Glob',   pattern: string }
  // …extend as needed

// A scripted arc, expanded against context+state+vibe to emit beats.
type Scenario = {
  id: string                // 'debug-fix', 'explain-code', …
  match: (intent: Intent, ctx: RepoContext, state: SessionState) => number  // score
  expand: (ctx: RepoContext, state: SessionState, vibe: VibePack) => Beat[]
}

// Voice & tone.
type VibePack = {
  id: string
  openers:    Phrase[]
  fillers:    Phrase[]      // mid-stream filler ("Looking at this…")
  closers:    Phrase[]
  toolPreambles: Record<ToolCall['name'], Phrase[]>
  emphasis:   'plain' | 'enterprise' | 'doomer' | 'zen' | 'hype' | …
  jitter:     JitterCurve   // streaming pacing tied to vibe (zen = slow & sparse)
}

type Phrase = string | ((slots: Slots) => string)
type Slots  = { file?: string, symbol?: string, lang?: string, … }

// Per-session memory.
type SessionState = {
  turns:     Turn[]
  seenFiles: Set<string>
  toolHistory: ToolCall[]
  vibe:      VibePack
  rng:       SeedableRNG
}

// What the Director infers from input.
type Intent = {
  category: 'debug' | 'explain' | 'refactor' | 'add-feature' | 'review'
          | 'plan' | 'general'
  keywords: string[]
  fileHints: string[]   // file paths/names mentioned in input
}

// Lazily loaded repo facts.
type RepoContext = {
  cwd: string
  files: FileEntry[]            // path, size, ext, mtime
  git?: { branch, head, recentCommits, dirty }
  read: (path: string) => Promise<string | null>  // gated by guardrails
  pickFiles: (n: number, opts?: PickOpts) => FileEntry[]
}
```

## 8. Director & Scenarios

### 8.1 Intent classification (rule-based)

A small keyword-and-pattern matcher. No ML.

- Strong keywords: `fix`, `bug`, `error` → `debug`
- `explain`, `what does`, `how does` → `explain`
- `refactor`, `clean up`, `extract` → `refactor`
- `add`, `implement`, `build` → `add-feature`
- `review`, `audit` → `review`
- `plan`, `design`, `architect` → `plan`
- File-name hints: any token matching a file in `RepoContext.files` becomes a `fileHint`

If nothing matches → `general` (a low-information arc).

### 8.2 Scenario library (v1 set)

| Scenario | Trigger | Beats sketch |
|---|---|---|
| `debug-fix` | `debug` intent | Read suspect file → Grep symbol → Read related file → Edit → Bash(test) → ✓ |
| `explain-code` | `explain` intent | Read file → "Here's how this works…" prose → reference line numbers |
| `refactor` | `refactor` intent | Read → Grep usages → Edit (multi-file) → Bash(test) → ✓ |
| `add-feature` | `add-feature` intent | Plan-prose → Read existing → Edit (new file) → Edit (wire-up) → Bash(test) → ✓ |
| `review` | `review` intent | Glob → Read several → Markdown bullet review with file:line refs |
| `plan` | `plan` intent | Markdown plan with phases; no edits |
| `general` | fallback / ambient | Light mix of Read + chat; no edits |
| `failed-test-then-fix` | random in ambient | Bash(test) → red output → Read → Edit → Bash(test) → ✓ |
| `cargo-cult-debug` | (doomer vibe only) | Edit, Bash, Edit, Bash, … never converging |

Scenarios score the input via `match()`; Director picks the highest scorer.
Stateful tweak: scenarios used in recent turns get a small score penalty so
the same arc doesn't repeat in REPL/ambient.

### 8.3 Beat composition rules

- Every scenario opens with a chat beat from `vibe.openers`.
- Tool beats are bracketed with `vibe.toolPreambles[toolName]`.
- Pauses are inserted between beats with vibe-tuned distributions.
- Closers come from `vibe.closers`, optionally with a fake summary line.
- All free text passes through a slot-filler that injects real file paths,
  symbol names, and counts pulled from `RepoContext`.

## 9. Vibe System

### 9.1 Day-one vibes

| Vibe | Voice | Sample opener |
|---|---|---|
| `default` | Neutral, mimics real Claude Code | "I'll take a look at this." |
| `enterprise` | Corporate, hedged, process-y | "Happy to help. Per our coding standards, let me first survey the affected modules." |
| `doomer` | Bleak, defeated competence | "Alright. This codebase is cursed but I'll try." |
| `zen` | Minimalist, koan-ish, sparse | "Reading." |
| `hype-bro` | Overcaffeinated, exclamation-heavy | "OKAY LET'S GOOO. This is going to be SO clean." |

A sixth, `intern` (overconfident, occasionally wrong on purpose), is a stretch
goal — the comedy lands well but authoring quality is hard to nail.

### 9.2 Vibe pack structure

A vibe is a TS module exporting a `VibePack`. Each pack provides phrase pools
for openers, closers, fillers, and tool preambles, plus a `JitterCurve` so
streaming feel matches voice (zen streams slowly with long pauses; hype-bro
fires fast with short pauses).

### 9.3 Authoring guidelines

- Phrase pools should have ≥5 variants each to avoid obvious repetition.
- Slot-fill placeholders use `{file}`, `{symbol}`, `{count}`, `{lang}`.
- Avoid timeless dates, brand names, real people.

## 10. Repo Context Engine & Safety

### 10.1 What it reads

The **codebase root** defaults to `process.cwd()`; override with `-C <path>` /
`--cwd <path>`. All reads below are scoped to this root.

- **Always:** root directory listing (one level + light recursion to depth 3).
- **Always:** git state via `git rev-parse`, `git log -10`, `git status --porcelain`.
- **On demand:** file *contents*, only when a scenario needs to slot in a
  realistic snippet or "Read" a file.

### 10.2 Safety guardrails

Hard rules enforced in `context/safety.ts`:

1. **Path containment.** Resolved real-path must be inside `cwd`. No symlinks
   that escape. No `..` after resolution.
2. **Secret blocklist** (deny by glob, case-insensitive):
   - `.env*`, `*.pem`, `*.key`, `id_rsa*`, `*.crt`, `*.p12`, `*.pfx`
   - `**/.ssh/**`, `**/.aws/**`, `**/.gnupg/**`, `**/.config/gh/**`
   - `**/credentials*`, `**/secrets*`, `**/*token*`, `**/*password*`
   - `**/.netrc`, `**/.npmrc`, `**/.pypirc`, `**/.docker/config.json`
3. **Gitignore-aware.** Any path ignored by `.gitignore` is skipped.
4. **Size cap.** Skip any file > 100 KB.
5. **Binary skip.** Detect by extension allowlist (`.ts .tsx .js .jsx .py .rb
   .go .rs .java .kt .c .h .cpp .hpp .cs .swift .md .json .yaml .yml .toml
   .html .css .scss .sql .sh`) and a quick null-byte sniff.
6. **Total budget.** Aggregate read content per session ≤ 500 KB. Once hit,
   `read()` returns `null` for the rest of the session and the engine
   silently uses purely fabricated content.
7. **Read-only.** No `write`, `unlink`, `chmod`, `exec` paths in the engine.
   The codebase has no write APIs against user files.
8. **No content leaves the process.** Read content is used only to seed
   slot-fillers and rendered output. Never persisted, never transmitted.
9. **Opt-out.** `--sandboxed` disables file reads entirely (degrades to fully
   fabricated output).
10. **First-run consent.** On first invocation in a directory, print a one-line
    notice: "bluff-code reads files in this directory to make output look
    plausible. `--sandboxed` to disable. Ack? [Y/n]" — store ack in
    `~/.config/bluff-code/acks.json`.

### 10.3 Cache

- File reads are cached per session (one read per file max).
- Listing is cached per session.

## 11. Session State

Stateful only **within a single REPL session**. One-shot and ambient runs do
not persist state across invocations.

What we track:

- **Turn history.** User input + emitted beats per turn. Used to avoid
  scenario repeats and to enable callback prose ("as I noted earlier in
  `auth.ts` …").
- **Seen files.** Files we've fake-Read; the next turn won't fake-Read them
  again gratuitously.
- **Tool history.** Sequence of fake tool calls; informs which scenarios we
  avoid.
- **Vibe.** Persists for the session unless `/vibe <name>` is issued.
- **Seed.** RNG seed for reproducibility.

State is in-memory only. No disk persistence in v1.

## 12. Pacing & Jitter

Realistic streaming is half the joke. Token emission timing is modeled, not
random.

- **Inter-token delay** is sampled from a per-vibe distribution (mean,
  std-dev, occasional long-pause spikes).
- **Tool-call timing**: spinner shows for a sampled duration (Read: 0.2–0.6s,
  Grep: 0.4–1.2s, Bash: 0.8–4s, Edit: 0.3–0.7s).
- **Inter-beat pause**: sampled with vibe bias.
- **Backspace artifacts** (optional, off by default): occasionally erase and
  retype a word for "self-correction" realism.

Calibration target: feel comparable to Sonnet/Opus streaming at ~40 tok/s
average with realistic jitter.

## 13. Tool-Call Mimicry

### 13.1 Visual format

Mirror Claude Code's box style precisely:

```
● Read(src/auth/login.ts)
  ⎿  Read 142 lines

● Grep(pattern: "validateSession", glob: "**/*.ts")
  ⎿  Found 4 matches in 3 files

● Edit(src/auth/login.ts)
  ⎿  Updated src/auth/login.ts with 7 additions and 2 removals

● Bash(npm test -- auth)
  ⎿  PASS  src/__tests__/login.test.ts
       ✓ accepts valid credentials (14 ms)
       ✓ rejects expired sessions (8 ms)
     Tests: 2 passed, 2 total
```

### 13.2 Fake side effects

- **Read**: emits a real line count (from cached read of the file).
- **Grep**: emits a plausible match count; if file content is available, picks
  real files that contain the pattern; otherwise fabricates plausible filenames.
- **Edit**: emits "X additions, Y removals"; uses small numbers (1–15).
  Never actually modifies the file.
- **Bash**: emits scripted output for known commands (`npm test`, `cargo
  test`, `go test`, `pytest`, `tsc --noEmit`, `git status`, `ls`). Falls back
  to one of several generic outputs.
- **Glob**: emits real matched paths from `RepoContext`.

### 13.3 Cosmetic slash commands (REPL only)

- `/init` — pretends to scan the repo and emit a fake `CLAUDE.md` plan.
- `/plan` — enters a fake "plan mode" with markdown plan output and a
  pretend approval prompt.
- `/cd <path>` — switch the codebase root for the rest of the session (real).
- `/clear` — clears scrollback (real).
- `/vibe <name>` — switches vibe pack (real).
- `/seed <n>` — re-seeds RNG (real).
- `/exit` — quits.

## 16. Out of Scope (v1)

- Real LLM fallback (no `--real` flag).
- Network calls of any kind.
- Voice input/output.
- Image generation or rendering.
- Real file editing or shell execution.
- Plugin / extension API for third-party scenarios.
- Multi-user / shared session state.
- Telemetry, analytics, error reporting.

## 17. Risks & Mitigations

| Risk | Mitigation |
|---|---|
| Output looks too obviously canned over long sessions | ≥5 phrase variants per pool; recency penalties on repeated scenarios; seed-able RNG |
| Reading user files exposes secrets in output | Hard blocklist + path containment + size cap + budget cap (§10.2) |
| Misuse for adversarial deception (interview cheating, etc.) | Positioning + README framing; not a technical fix |
| Trademark / brand confusion with Claude Code | README disclaimer; near-miss visual cues; don't claim association |
| Maintenance burden of hand-authored phrase pools | Author scenarios as composable beat fragments; share fillers across vibes |

## 18. Glossary

- **Beat** — atomic unit of scripted output (chat, tool, pause, etc.).
- **Scenario** — a scripted arc that expands into a sequence of beats.
- **Vibe** — a voice/tone pack governing phrase selection and pacing.
- **Slot-fill** — replacing template placeholders (`{file}`) with real values
  pulled from repo context.
- **Ambient mode** — no-input loop mode designed for the cafe-bluffer use case.
- **Director** — the component that turns input + state into a beat sequence.
